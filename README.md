## Testing local changes with Volt

The `dev` loader above reads `origin/dev` from GitHub. It does not include
uncommitted changes in your working tree.

Keep the repository checkout at:

```text
%LOCALAPPDATA%\Volt\workspace\hydroxide\local
```

Then run the local entrypoint in Volt:

```lua
loadstring(readfile("hydroxide/local/local.lua"), "local.lua")()
```

The loader reads every imported module directly from that checkout. Edit the
files normally and run the entrypoint again to test the new working tree. This
does not require a commit or push and does not replace Volt's normal Hydroxide
cache.

## Helper modules

Reusable behavior that must work in both Hydroxide and its generated scripts
lives under `modules/`. Hydroxide imports these modules through its normal
loader; generated scripts load the same source file from the configured fork.

`modules/Helpers.lua` creates the real `oh` helper bundle. It imports modules from
the running Hydroxide session, reads them from the local Volt workspace, or
downloads them from the configured fork and branch. Loaded modules are cached
and exposed through lowercase role-based names such as `oh.closure`,
`oh.targeting`, `oh.lifecycle`, and `oh.remote`. Configuration values are
explicitly grouped under `oh.constants`, while live values belong to `oh.state`.

`modules/Closure.lua` is the first shared helper. It inventories game
closures and locates a closure using its script, name, upvalue, and constants.
It can also recursively find live string constants in a script and its nested
protos, allowing game-specific scripts to resolve current validation values
instead of copying them from a decompile snapshot. `findUpvalue` searches live
closures owned by a script and returns the first upvalue accepted by a consumer
predicate.
It accepts an injected executor adapter for behavioral tests and uses Volt's
documented closure/debug functions when loaded directly.

Hydroxide's UI pages call the same module methods an in-session script can
call. After launch they are also indexed on `oh.Api`. The first slice of that
surface is the relationship graph a person already follows by clicking:

- `ScriptScanner.Scan` / `ModuleScanner.Scan` plus `ScannerResults.Describe`
  read a script's path, protos, constants, and environment without a decompile
  dump.
- `ScriptGraph.Describe` adds the links the UI already uses: Signal Spy
  connections on the instance, Remote Spy calls whose `script` is this one,
  and Closure Spy hooks owned by the script together with their callers.
- `ClosureSpy.GetScript` / `GetScriptPath` is the Get Script Path action.
- `RemoteSpy.CallsFrom` / `DescribeCall` is the Get Calling Script action
  run in reverse: from a script to the remotes it fired.
- `SignalSpy:Summarize` is Inspect Signals without stealing the person's
  current Signal Spy target. `Inspect` remains the UI-opening action.

The live MCP bridge stays generic instance inspection (`roblox_status`,
script list/read, `roblox_eval`). It does not catalog these Hydroxide
methods.

`oh.targeting.nearestVisiblePlayer(options)` selects the nearest eligible,
on-screen player and returns the most visible body part, averaged visible aim
position, distance, and visibility score. `options.maxDistance` can constrain
the search.

`oh.lifecycle.bindTool(toolName, callback)` binds matching tools in the
Backpack or character, rebinds them after respawn, and returns a session with
`stop()`. The callback receives a per-tool scope with `connect()` and `add()`
for cleanup that follows tool replacement and respawn.

The game-specific knife test in `examples/knife_validation.lua` uses targeting
to retarget the game's original throw call. The original validation token and
downstream collision flow remain untouched and are not part of Hydroxide's
generic ScriptBuilder API.

`ohaux.lua` remains available for scripts generated by older Hydroxide builds.

# Hydroxide
<i>Lua runtime introspection and network capturing tool for games on the Roblox engine.</i>

## Features
* Upvalue Scanner
    * View/Modify Upvalues
    * View first-level values in table upvalues
    * View information of closure
* Constant Scanner
    * View/Modify Constants
    * View information of closure
* Script Scanner
    * View general information of scripts (source, protos, constants, etc.)
    * Retrieve all protos found in GC
* Module Scanner
    * View general information of modules (return value, source, protos, constants, etc.)
    * Retrieve all protos found in GC
* RemoteSpy
    * Log calls of remote objects (RemoteEvent, RemoteFunction, BindableEvent, BindableFunction)
    * Ignore/Block calls based on parameters passed
    * Traceback calling function/closure
* SignalSpy
    * Inspect reflected `RBXScriptSignal` events and their current connections
    * Follow accessible connection closures into ClosureSpy
    * Show verified script, Lua state, and Actor-state relationships
* ClosureSpy
    * Log calls of closures
    * View general information of closures (location, protos, constants, etc.)

More to come, soon.
